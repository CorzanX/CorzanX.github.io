6. Challenges and Solutions

Challenge Solution
Avoid exposing API keys Store DEEPSEEK_API_KEY in an environment variable instead of source code
Online model cannot directly see local files Read the local file in Python and send only the selected content to the API
Local model may not be installed by default Install Ollama and pull the Qwen model before running the demo
Local model responses may be slower Use a smaller Qwen model if memory or speed is limited
IDE extensions require separate configuration Prepare a Continue configuration example for both DeepSeek and Ollama

7. Reflection

The online model and the local model are useful in different situations.

DeepSeek is easier to start with once the API key is configured. It does not require local model storage or local GPU memory, and the response quality is generally strong. It is suitable for file analysis, explaining reports, and handling tasks that need stronger reasoning.

Ollama with Qwen is more private and independent because the model runs locally. It is useful for code explanation and quick experiments without sending code to an online service. The tradeoff is that installation, model download, and local hardware performance matter more.

For my workflow, the online model is better for polished explanations and broader reasoning, while the local model is better for private code experiments and lightweight refactoring. IDE integration is the most convenient form because it keeps the model close to the code I am editing.

8. Conclusion

In this assignment, I prepared an online DeepSeek file analysis agent, a local Ollama Qwen interaction demo, and an IDE integration example. The work shows how online and local LLMs can be used not only for chatting, but also for file analysis, code explanation, and refactoring.

The final report includes the DeepSeek file-analysis result, the Ollama Qwen terminal interaction, and the VSCode Continue IDE integration evidence.
